# AmneziaWG VPN Server

Самостоятельный VPN-сервер на AmneziaWG 2.0+. Лицензия MIT (см. `LICENSE`).

English: [README.md](README.md).

Заметки по безопасности для оператора: [SECURITY.md](SECURITY.md).

## Архитектура

- Веб-панель на Go
- SQLite как единственный источник истины
- AmneziaWG в отдельном контейнере
- Docker Compose
- Встроенное React SPA (`go:embed` `dist`)
- Бэкапы БД в `tar.zst` (скачать / загрузить в панели)

## Бэкап и восстановление (M8)

- В панели **Бэкап** — выпадающий список: **Скачать** отдаёт свежий
  `backup-YYYY-MM-DD.tar.zst` (манифест + SQLite), **Загрузить**
  восстанавливает из архива. Паролей и age-ключей нет.
- `panel backup create` / `panel backup list` пишут и показывают архивы
  в каталоге бэкапов. `panel restore <archive>` готовит восстановление,
  которое `panel-init` применяет при следующем перезапуске.
- Восстановление оставляет прежнюю БД на диске как копию для отката.
  Загрузка через веб применяется в процессе (без рестарта), когда это
  возможно.

## Установка

С машины оператора запустите русский мастер. Enter принимает значение
в квадратных скобках. Для SSH по паролю на хосте оператора нужны
`sshpass` или `expect` (`brew install sshpass` / `apt install sshpass`).

```sh
./bootstrap.sh
```

Мастер спрашивает IP сервера, SSH-пользователя (`[root]`), пароль или
ключ (по умолчанию пароль; ключ из `~/.ssh` не берётся, пока не ответите
`ключ` или `2`), домен панели (пусто = панель на IP сервера, затем порт
панели `[8443]`), порт панели `[443]` если домен задан (пусто = TLS на
443) и домен для VPN-клиентов (пусто = публичный IP — его никогда не
копируют с hostname панели). AmneziaWG остаётся на UDP 443, корень
деплоя — `/opt/amnezia-vpn`.

Когда репозиторий будет на GitHub, тот же мастер можно скачать так
(подставьте `OWNER`):

```sh
curl -fsSL https://raw.githubusercontent.com/OWNER/amnezia-vpn-server/main/bootstrap.sh -o bootstrap.sh && bash bootstrap.sh
```

CI / флаги: `bootstrap.sh` ходит по SSH на VPS, запускает `install.sh`,
создаёт администратора, печатает URL панели и временный пароль. Панель
и VPN-эндпоинт независимы. Флаги: `--ip`, `--panel-domain` (алиас
`--domain`), `--vpn-domain` (алиас `--client-domain`), опционально
`--panel-port` (без домена панели CI по умолчанию ставит 8443; не
используйте 8787 — это loopback-порт панели). `--panel-domain`
**не** привязывает VPN-клиентов; это делает только `--vpn-domain` /
`--client-domain`. Восстановление — загрузка в панели (Бэкапы) и не
меняет пользователя панели (T-155).

```sh
./bootstrap.sh --ip HOST --panel-domain panel.example.com --vpn-domain example.com
```

Опциональный TLS-порт панели (Let's Encrypt по-прежнему использует
TCP 80 для HTTP-01):

```sh
./bootstrap.sh --ip HOST --panel-domain panel.example.com --vpn-domain example.com --panel-port 8443
```

`install.sh` остаётся установщиком на сервере (Ubuntu/Debian
24.04/22.04, Docker Compose v2.24.2+):

```sh
./install.sh [--root DIR] [--awg-port PORT] [--vpn-subnet CIDR]
             [--panel-domain FQDN] [--vpn-domain FQDN] [--panel-port PORT]
```

Установщик создаёт раскладку (data/config/status/backups), ставит
nftables и unit forward-accept, собирает и запускает стек, держит панель
только на loopback за nginx, когда задан домен или `--panel-port`. Без
`bootstrap.sh` инициализация приложения по-прежнему:

```sh
docker compose --env-file versions.lock run --rm panel-init \
  /app/panel server init 10.8.0.1/24 443 --endpoint <public-ip>:443 --dns 1.1.1.1,8.8.8.8
ssh -L 8787:127.0.0.1:8787 root@<server-ip>
```

С доменом панели (`--panel-domain` / `--domain`, T-121) панель получает
HTTPS (nginx + Let's Encrypt). HTTP-01 остаётся на TCP 80. TLS слушает
443, если не задан `--panel-port` (`https://PANEL_DOMAIN:PORT`).
`--vpn-domain` / `--client-domain` пишет в клиентские конфиги
`<fqdn>:<awg-port>` вместо публичного IP: клиенты резолвят домен при
подключении. Установщик заранее проверяет DNS. На старом хосте
`install.sh` отказывается работать, если запись больше не совпадает
(пока домен не вернут обратно или новый хост не закончит установку).

Чтобы восстановить существующую БД после установки, загрузите архив в
панели (Бэкапы). Это восстановление не меняет пользователя панели. CLI
`panel restore <archive>` остаётся для операторов без веб-UI.
Перенос всего деплоя на другой VPS — раздел **Переезд на другой VPS**.

## Переезд на другой VPS

Чеклист (проверьте на запасном хосте до того, как это понадобится):

1. Пока **старая** панель ещё доступна, скачайте бэкап `tar.zst` из
   Бэкапов.
2. С ноутбука запустите `./bootstrap.sh` (мастер) или те же флаги на
   **новый** IP. Задайте `--panel-domain` / `--vpn-domain` как сейчас.
3. Войдите в **новую** панель с временным паролем, который напечатал
   bootstrap.
4. Загрузите архив в Бэкапах. Пользователь панели, пароль и TOTP
   **не** меняются (T-155).
5. Если клиенты используют `--vpn-domain`, направьте A-запись этого
   домена на новый IP. Клиенты переподключатся; конфиги заново выдавать
   не нужно.
6. Если клиенты ходили на старый IP, в каждом конфиге нужно править
   endpoint.

## Статус

**1.0** — установка через `./bootstrap.sh` (мастер) или флаги, затем
`install.sh` на VPS. Лицензия: MIT (`LICENSE`). Теги образов Compose и
`application_version` в бэкапе остаются **2.0.0** (поколение стека);
публичная метка продукта — 1.0.

В 1.0:

- TLS панели для пользователей: nginx + Let's Encrypt при
  `--panel-domain`; без домена — HTTPS на `--panel-port` (CI по
  умолчанию 8443, самоподписанный). Loopback `8787` остаётся портом
  панели в compose.
- Ограничение частоты логина (T-105).
- TOTP для входа в панель.
- CLI `panel auth set-password` (сброс пароля). Восстановление
  (загрузка в панели / `panel restore`) не подменяет пользователя
  панели.
- Независимые hostname панели и VPN (`--panel-domain` /
  `--vpn-domain`).

Вне 1.0: T-104 TLS внутри процесса панели (TLS в Go вместо nginx) и
T-106 RBAC.
