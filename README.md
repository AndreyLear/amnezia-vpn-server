# AmneziaWG VPN Server

Свой VPN на своём сервере: одна команда в терминале — и через несколько минут
у вас работает VPN с панелью управления в браузере. Клиенты добавляются в
пару кликов, подключение — по QR-коду.

Работает на AmneziaWG: трафик маскируется под обычный, поэтому проходит там,
где обычный VPN блокируют.

## Что понадобится

**Сервер** с root-доступом по SSH. Требования скромные:

| | Минимум | Комментарий |
| --- | --- | --- |
| Система | Ubuntu 24.04 | рекомендуется; Ubuntu 22.04 и Debian 12 тоже принимаются |
| Процессор | 1 ядро | проверено на 1 ядре: установка 3–5 минут, скорость до 45 МБ/с |
| Память | 1 ГБ, лучше 2 ГБ | при 2 ГБ остаётся запас на рост числа клиентов |
| Диск | 10 ГБ | образы и база занимают меньше 1 ГБ |
| Порты | UDP 4500, TCP 443 или 8443 | плюс TCP 80, если берёте сертификат Let's Encrypt |

Такой сервер стоит 3–5 долларов в месяц у большинства хостингов. Считайте
трафик: VPN тратит столько же, сколько тратят ваши пользователи.

**Какую систему выбрать.** Берите Ubuntu 24.04 — на ней всё проверено.
AmneziaWG ставится из репозитория `ppa:amnezia/ppa`, это механизм Ubuntu, и
оттуда приходит модуль ядра: шифрование работает в ядре, а не в отдельном
процессе, отсюда скорость. Ubuntu 22.04 подходит так же.

Debian 12 установщик примет, но мы его не проверяли: PPA для Debian не
родной, и после обновления ядра модуль может не пересобраться — тогда туннель
перестанет подниматься. Остальные системы (Rocky, Alma, Fedora, Arch, Alpine)
установщик останавливает сразу.

Выигрыша от другой системы нет. Скорость определяют канал хостинга и число
ядер, а не дистрибутив.

**Домен** — по желанию. Без него всё работает по IP-адресу сервера. С доменом
получите нормальный сертификат вместо самоподписанного и сможете переехать на
другой сервер, не меняя настройки у пользователей.

**Ваш компьютер** — Mac, Linux или Windows.

На Mac и Linux откройте терминал. Для входа на сервер по паролю поставьте
`sshpass`:

```sh
brew install sshpass          # macOS
sudo apt install sshpass      # Ubuntu, Debian
```

На Windows установщик не запустится ни в PowerShell, ни в командной строке: он
написан для оболочки Unix. Поставьте WSL — это Ubuntu внутри Windows, вторая
машина не нужна. Откройте PowerShell от имени администратора:

```powershell
wsl --install
```

Команда поставит Ubuntu и попросит перезагрузить компьютер. После перезагрузки
Ubuntu запустится сама и спросит имя пользователя и пароль — придумайте любые,
они живут только внутри неё. Затем поставьте `sshpass`:

```sh
sudo apt install sshpass
```

Дальше открывайте Ubuntu из меню «Пуск» и вводите там все команды из этой
инструкции. В PowerShell они не работают: перенос строки и кавычки там
разбираются по-другому.

WSL работает на Windows 11 и на Windows 10 версии 2004 и новее. Ставится он
один раз: дальше Windows ничем не отличается от Mac или Linux.

**Время** — около пяти минут.

## Установка

Скачайте мастер установки и запустите:

```sh
curl -fsSL https://raw.githubusercontent.com/AndreyLear/amnezia-vpn-server/main/bootstrap.sh -o bootstrap.sh
bash bootstrap.sh
```

Мастер спросит адрес сервера, пароль или ключ, домен. Enter принимает значение
в квадратных скобках — если сомневаетесь, жмите Enter.

Всё то же самое можно задать сразу:

```sh
./bootstrap.sh --ip 203.0.113.10 --vpn-domain example.com
```

### Что произойдёт

Мастер подключится к серверу и покажет девять шагов:

```
bootstrap: [1/9] Проверяю систему
bootstrap: [2/9] Устанавливаю Docker
bootstrap: [3/9] Настраиваю ядро и сетевые оптимизации
bootstrap: [4/9] Устанавливаю AmneziaWG
bootstrap: [5/9] Разворачиваю файлы на сервере
bootstrap: [6/9] Измеряю канал сервера
bootstrap: [7/9] Скачиваю готовые образы
bootstrap: [8/9] Запускаю сервисы
bootstrap: [9/9] Проверяю установку
```

В конце он напечатает адрес панели, логин, временный пароль и отпечаток
сертификата. **Сохраните это** — пароль больше нигде не хранится.

```
Panel:     https://203.0.113.10:8443
Login:     admin
Password:  rZksiVMoEcPXsCQtFowec1+e
Endpoint:  example.com:4500
```

### Что включается само

Четыре вещи установщик решает за вас, потому что иначе о них пришлось бы
помнить.

**Защита SSH от перебора паролей.** Любой сервер с белым адресом перебирают
круглосуточно, с первого же часа. Ставится `fail2ban`: пять неудачных попыток
за десять минут — час бана. Порт туннеля не трогается никогда: там нет
паролей, которые можно подобрать, а бан отрезал бы живого человека.

**IPv6 внутри туннеля** — если у сервера он есть и **работает**. Проверяется
не наличие адреса, а живой отклик наружу: у части хостеров IPv6 настроен
наполовину, адрес выдан, а трафик не ходит.

Зачем это нужно: YouTube, Instagram и почти всё крупное живёт сразу в двух
версиях протокола. Если туннель несёт только IPv4, весь их трафик протискивается
в одну трубу, а вторая половина мощностей остаётся недоступной. Это и есть
частая причина «страница открылась, а видео не грузится».

**Сторож за резолвером и туннелем.** Раз в минуту проверяется, что резолвер
ещё отвечает и что туннель ещё пишет свой статус. Сервис, переставший это
делать, перезапускается — после двух отказов подряд и не чаще раза в десять
минут.

Зачем: контейнер может быть поднят и бесполезен одновременно. Для Docker это
успех, и штатный перезапуск такого случая не видит — зависший резолвер молчит
до тех пор, пока кто-нибудь не пожалуется. Рукопожатия клиентов сторож при
этом не трогает: люди законно бывают офлайн, и перезапускать из-за этого
туннель было бы вредом без причины.

**Проверка обновлений раз в сутки.** Сервер спрашивает GitHub, вышел ли выпуск
новее, и панель показывает ответ. Ничего не скачивается и не ставится само:
обновиться — ваше решение.

Зачем: блокировки меняются, и то, что обходило их в марте, к осени может
перестать. Выпуски здесь — это в том числе починенный обход. Сервер, который
не знает о вышедшем выпуске, не обновится никогда, а хозяин узнает о проблеме
от пользователей.

Если GitHub у вас недоступен, проверка молча не удастся: жаловаться на это
каждый день бессмысленно. Причину видно на странице обновления, если вы туда
зайдёте.

### Как выключить, если не нужно

Каждая вещь выключается флагом при установке:

```bash
./bootstrap.sh --ip 203.0.113.10 --no-ipv6        # туннель только IPv4
./bootstrap.sh --ip 203.0.113.10 --no-fail2ban    # без защиты SSH
./bootstrap.sh --ip 203.0.113.10 --no-watchdog    # без сторожа
./bootstrap.sh --ip 203.0.113.10 --no-update-check  # не спрашивать GitHub
```

Про `--no-update-check` стоит знать причину: любая проверка обновлений
сообщает GitHub адрес вашего сервера. Сервер, который должен быть незаметным,
раз в сутки говорит о себе стороне за пределами вашего контроля. Если это для
вас важнее, чем узнавать о выпусках, — флаг ваш. Следить за выпусками тогда
придётся самому.

Те же флаги понимает `install.sh`, если вы запускаете его на сервере сами.

**Выключить позже** — повторить установку с флагом; всё добавленное будет
убрано: правила, маршрутизация и адреса в конфигах клиентов.

```bash
./bootstrap.sh --ip 203.0.113.10 --no-ipv6
```

Обратно включается так же — флагом `--ipv6`.

Два обещания про это стоит знать точно:

- **Обновление версии никогда не меняет ваше решение.** Сервер, который
  работает без IPv6, после обновления работает без него же. Ничего не
  включается само на уже живущей установке — только на новой.
- **Выключение обратимо и полно.** Не «перестаём добавлять новое», а убираем
  ранее добавленное, при каждом запуске.

Одна честная оговорка: включение и выключение IPv6 **перезапускает туннель**.
Связь у всех клиентов прервётся примерно на **пятнадцать секунд** (по трём
замерам на живом сервере — 12, 13 и 16 секунд), после чего восстановится сама,
без вашего участия и без перевыпуска конфигов. Адрес интерфейса иначе не
сменить.

## Панель

Всё управление — в браузере, отдельного приложения не нужно.

**В шапке** — состояние сервера: загрузка процессора, памяти и диска плюс
состояние туннеля («Интерфейс поднят», «Интерфейс недоступен»). Если сервер
начал задыхаться, это видно сразу.

**Основная часть** — карточки клиентов. На каждой: имя, выданный адрес,
включён ли клиент, когда он в последний раз выходил на связь и сколько
трафика получил и отправил.

**Кнопка «Бэкап»** — скачать или загрузить файл со всеми настройками.

Панель открывается по одному и тому же адресу и с включённым VPN, и без него.
Сервер держит собственный DNS внутри туннеля: для подключённых устройств он
отвечает на домен панели её адресом внутри туннеля. Сертификат при этом
остаётся валидным — имя не меняется.

## Клиенты

Клиент — это одно устройство: телефон, ноутбук, роутер. У каждого свои ключи,
поэтому отключение одного не трогает остальных.

### Как добавить

Нажмите кнопку добавления и введите имя — любое понятное вам: «телефон»,
«ноутбук жены», «роутер на даче». Панель сама выдаст адрес и создаст ключи.

Дальше устройство подключают одним из двух способов.

**QR-код** — для телефона. Откройте меню клиента → **QR-код** и отсканируйте
его в приложении. Больше ничего вводить не нужно.

**Файл настроек** — для компьютера и роутера. Меню клиента → **Скачать
конфиг**, затем импортируйте файл в приложение. Файл создаётся в момент
скачивания и нигде не хранится.

### Что ещё можно

- **Отключить** — клиент перестаёт подключаться, настройки у него остаются:
  устройство потеряли или доступ нужно приостановить
- **Включить обратно** — тем же переключателем, заново раздавать ничего не надо
- **Удалить** — ключи стираются, старые настройки перестают работать навсегда
- **Описание** — заметка для себя: кому выдали, когда, зачем

### Сколько клиентов

Ограничения нет: адреса выдаются из подсети `10.8.0.0/24`, это 253 устройства.
Упрётесь в это — упрётесь в канал сервера гораздо раньше.

## Приложения

Сервер говорит по протоколу AmneziaWG, поэтому подойдёт любой клиент, который
его понимает.

**AmneziaWG** — приложение под сам протокол, ничего лишнего:

- iOS — [App Store](https://apps.apple.com/app/amneziawg/id6478942365)
- Android — [Google Play](https://play.google.com/store/apps/details?id=org.amnezia.awg)
- Windows — [релизы на GitHub](https://github.com/amnezia-vpn/amneziawg-windows-client/releases).
  Берите файл `amneziawg-amd64-<версия>.msi`. Вариант `arm64` — для ноутбуков
  на процессорах ARM, вариант `windows7` — для Windows 7 и 8

**AmneziaVPN** — общий клиент Amnezia, умеет несколько протоколов сразу.
Есть под Windows, macOS, Linux, Android и iOS: [amnezia.org/downloads](https://amnezia.org/downloads)

Ставить оба не нужно. Если пользуетесь только этим сервером, берите AmneziaWG:
он проще и делает ровно одно дело.

**Роутеры.** Подойдёт OpenWrt с пакетом `amneziawg` или Keenetic с поддержкой
AmneziaWG: настройте роутер как обычного клиента, и весь дом пойдёт через VPN
без настройки каждого устройства. Дальше — три вещи, которые стоит сделать
именно при такой схеме.

### Если туннель поднят на роутере

Устройства дома спрашивают имена у роутера, а не у нашего сервера: настройки
клиента до них не доходят. Поэтому три пункта ниже — не тонкая настройка, без
них дом работает не так, как вы думаете.

**1. Имена должен разрешать наш сервер.** Укажите в роутере единственный
сервер имён `10.8.0.1` и удалите остальные, включая полученные от провайдера
по DHCP.

**2. Выключите в роутере DNS-over-HTTPS и DNS-over-TLS.** Иначе первый пункт
ничего не изменит: роутер продолжит спрашивать имена у Cloudflare или Google
по 443 порту, мимо туннеля. Это видно по замеру на живом Keenetic — за две
минуты ноль обращений к `10.8.0.1` и 240 пакетов к `1.1.1.1` и `8.8.8.8`.

**3. Выключите IPv6 от провайдера на подключении к интернету.** Туннель несёт
собственный IPv6, и он работает. Но если у устройства есть ещё и адрес от
провайдера, оно выберет его — и трафик уйдёт мимо VPN с вашим настоящим
адресом. В Keenetic это «Параметры IPv6» → «Настройка IPv6» → отключена.

**Как проверить.** С любого устройства в доме — не с самого роутера:

```sh
curl -6 https://ifconfig.co
```

Ответ должен быть адресом вашего сервера. Адрес провайдера означает, что часть
трафика идёт мимо туннеля.

**Про DNS панель скажет сама.** Если клиент передаёт данные через туннель, а
имена у нас не спрашивает, в его строке появится жёлтый значок: «Нет запросов к
нашему резолверу за последние 10 минут». Ничего настраивать для этого не нужно:
сервер видит, кто к нему обращается, и молчание заметно так же, как обращение.

Значка нет — либо всё в порядке, либо говорить пока не о чем: клиент не на
связи или только что подключился.

У клиента-роутера значок говорит только про сам роутер. Устройства дома скрыты
за ним: все их запросы выходят с одного адреса, и если роутер изредка
спрашивает нас о своём, значка не будет, даже когда ноутбук в это время ходит в
чужой DNS. Для дома надёжнее проверка из раздела выше — та, что с `curl`.

**MTU.** Роутер на проводе обычно несёт пакеты крупнее, чем телефон в
мобильной сети, а сервер по умолчанию рассчитан на телефон. Поднять значение
для одного клиента можно в панели: карточка клиента → MTU → «Изменить». Это
ускорит отдачу от дома наружу; скорость в обратную сторону задаётся сервером и
общая для всех.

## Частые ситуации

### Как сменить пароль панели

В панели такой формы нет намеренно: пароль меняется командой на сервере,
поэтому его нельзя подобрать через браузер.

```sh
ssh root@203.0.113.10 "cd /opt/amnezia-vpn && docker compose --env-file versions.lock \
  run --rm -T panel-init /app/panel auth set-password admin --password-stdin"
```

Команда попросит новый пароль и не покажет его на экране. Забыли старый —
ничего страшного, эта команда его не спрашивает.

### Бэкап: что это и как делать

Бэкап — это один файл со всем, что вы настроили: список клиентов, их ключи и
ключи самого сервера. Из него восстанавливается всё — на этом же сервере или
на новом. Настройки, которые вы раздали людям, после восстановления продолжают
работать, потому что ключи сервера тоже внутри.

**Как скачать.** В панели кнопка **Бэкап** → **Скачать**. Браузер сохранит
файл вида `backup-2026-08-23.tar.zst`. Он маленький, несколько килобайт.

**Как часто.** После каждого добавления или удаления клиентов. Отдельно —
перед переустановкой сервера и перед сменой хостинга.

**Где хранить.** Где угодно, кроме самого сервера: если сервер пропадёт,
бэкап на нём пропадёт вместе с ним.

**Как восстановить.** В панели **Бэкап** → **Загрузить**, выберите файл.
Клиенты вернутся сразу, перезапуск не нужен. Пароль панели останется тот,
который действует сейчас, — бэкап его не подменяет.

Если бэкап снят на другом сервере, панель спросит, какой адрес оставить
клиентам, — подробности в разделе про переезд.

### Переезд на другой сервер

Ключи сервера едут вместе с бэкапом, поэтому настройки у пользователей
остаются рабочими.

1. Пока старая панель доступна, скачайте бэкап: кнопка **Бэкап** → **Скачать**
2. Поставьте систему на новый сервер тем же мастером
3. Войдите в новую панель и загрузите скачанный файл: **Бэкап** → **Загрузить**
4. Панель увидит, что бэкап с другого сервера, и спросит, какой адрес
   использовать:
   - **оставить адрес из бэкапа** — если пользователи подключаются по домену.
     Переключите A-запись домена на новый сервер, и все подключатся сами
   - **использовать адрес этого сервера** — если подключались по IP. Тогда
     раздайте пользователям новые настройки из панели

### Обновление

Начиная с 2.9.0 сервер умеет обновляться сам: панель показывает, что вышел
новый выпуск, и обновление запускается кнопкой. Ssh для этого не нужен.

**Один раз придётся по-старому.** Служба, которая делает обновление, приезжает
вместе с выпуском — значит, на сервер, установленный раньше, её надо сначала
привезти. Первое обновление до 2.9.0 делается мастером, как ниже; все
следующие — кнопкой в панели.

Мастером обновляются и те, кто отключил проверку обновлений
(`--no-update-check`): без неё сервер не знает, что вышло.

Обновление — это тот же мастер, что и установка, запущенный ещё раз. Он помнит
настройки развёртывания и ничего не переспрашивает.

```sh
curl -fsSL https://raw.githubusercontent.com/AndreyLear/amnezia-vpn-server/main/bootstrap.sh -o bootstrap.sh
bash bootstrap.sh --ip 203.0.113.10
```

Флаги повторять не нужно: мастер помнит, что уже настроено на сервере. Домен
для клиентов остаётся прежним, даже если запустить обновление без
`--vpn-domain`. Вернуться на адрес сервера можно явно: `--vpn-domain ""`.

Клиентам ничего переиздавать не нужно: их настройки продолжают работать. На
время перезапуска связь прерывается на несколько секунд, и клиенты
восстанавливают её сами. Повторный запуск на уже установленном сервере занял
4 минуты 14 секунд при измерении со сборкой образов на месте; обычный путь,
когда образы скачиваются готовыми, короче.

Обновление меняет не только контейнеры, но и то, что живёт на самом сервере, —
правила брандмауэра, параметры ядра, службы. Выпуск, который добавляет
что-то новое (как IPv6 внутри туннеля), приезжает только так.

**Чего делать не стоит.** Раньше в этом разделе стояла пара команд с
`docker compose pull`. Они не обновляют: тег образа берётся из файла, который
лежит на сервере с прошлой установки, поэтому скачивается та же самая версия,
которая уже стоит. Хостовую часть эти команды не трогают вовсе.

### Удаление

```sh
ssh root@203.0.113.10 "bash /opt/amnezia-vpn/cleanup.sh"
```

Сначала покажет, что собирается удалить, и ничего не тронет. Чтобы выполнить,
добавьте `--yes`. Скрипт удаляет только то, что создал установщик.

### Что-то не работает

**Панель перестала открываться после повторной установки.** Так было до
версии 2.3.0: запуск установщика без флага домена возвращал панель на
loopback. Теперь настройки запоминаются, и повторный запуск ничего не меняет.
Если у вас старая версия — укажите домен явно ещё раз.

**Сайты открываются, но видео не грузится.** Почти всегда это MTU: мелкие
пакеты проходят, крупные — с видео — теряются по дороге. Установщик ставит
значение, которое переживает и мобильные сети, так что чаще всего достаточно
переустановки. Если после неё не помогло, попробуйте уменьшить MTU в самом
приложении на клиенте — например с 1340 до 1280.

**Клиент не подключается после переезда.** Проверьте, на какой адрес смотрит
домен: `dig +short example.com`. Он должен указывать на новый сервер.

**Панель не открывается.** Проверьте, что сервисы запущены:

```sh
ssh root@203.0.113.10 "docker ps"
```

Должны работать `amnezia-vpn-panel-1` и `amnezia-vpn-awg-1`.

## Как это устроено

Четыре контейнера на сервере: панель (она же хранит данные в SQLite),
AmneziaWG, DNS для подключённых клиентов и разовая задача инициализации.
Панель доступна только с самого сервера, наружу её отдаёт nginx с
сертификатом.

Данные — в SQLite, всё остальное восстанавливается из неё. Поэтому бэкап
базы возвращает и клиентов, и ключи сервера.

IPv6 у клиента отключается: иначе YouTube, Instagram и другие сайты с
поддержкой IPv6 шли бы мимо VPN, в обход туннеля.

Туннель работает на UDP 4500. Порт 443 выглядел бы удобнее — он открыт
почти везде, — но это порт QUIC, и мобильные операторы его придерживают,
чтобы притормозить видео. Туннель на нём попадал под то же ограничение
целиком: на замере он давал 20 Мбит/с против 45 на 4500 и 40 вообще без
туннеля. Порт 4500 занят протоколом IPsec, по которому работают
корпоративные VPN, поэтому его пропускают.

DNS внутри туннеля нужен из-за того, что панель живёт по тому же адресу, на
котором заканчивается туннель. Пакет, отправленный на этот адрес, в туннель
не уходит, а маршрут в обход iOS не создаёт — без подмены имени панель была
бы недоступна ровно с тех устройств, которые к ней подключены. Клиенту
выдаётся наш резолвер. На туннеле с IPv6 к нему добавляется публичный запасной:
если наш почему-то остановится, имена продолжат разрешаться и человек ничего не
заметит.

На туннеле без IPv6 запасного нет. С ним появлялась бы самая неприятная
поломка: страницы открываются, а видео не грузится, и понять почему
невозможно. Без него отказ виден сразу, а резолвер поднимает сторож — сам, в
течение минуты.
