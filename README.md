# AmneziaWG VPN Server

Скрипт ставит на ваш сервер VPN и панель, в которой клиенты добавляются кнопкой и подключаются по QR-коду. Установка — одна команда с вашего компьютера, около пяти минут.

VPN работает на AmneziaWG. Это WireGuard, у которого пакеты не похожи на WireGuard, поэтому его труднее заблокировать.

English: [README.en.md](README.en.md) · Безопасность: [SECURITY.md](SECURITY.md) · Разработка: [DEVELOPMENT.md](DEVELOPMENT.md)

## Что понадобится

**Сервер** с root-доступом по SSH:

| | Минимум | Заметки |
| --- | --- | --- |
| Система | Ubuntu 24.04 | Ubuntu 22.04 и Debian 12 установщик тоже принимает |
| Процессор | 1 ядро | установка на одном ядре занимает 3–5 минут |
| Память | 1 ГБ, лучше 2 ГБ | запас на рост числа клиентов |
| Диск | 10 ГБ | образы и база занимают меньше 1 ГБ |
| Порты | UDP 4500, TCP 443 или 8443 | плюс TCP 80, если нужен сертификат Let's Encrypt |

Такой сервер стоит 300–500 рублей в месяц. Следите за лимитом трафика: VPN тратит столько же, сколько клиенты.

Всё проверено на Ubuntu 24.04. На Debian 12 не проверялось: AmneziaWG ставится модулем ядра из `ppa:amnezia/ppa`, а это репозиторий Ubuntu, и после обновления ядра модуль может не собраться. Rocky, Alma, Fedora, Arch и Alpine установщик отклоняет сразу.

**Домен** не обязателен, без него всё работает по IP. Доменов может быть два, и они не зависят друг от друга:

- домен панели (`--panel-domain`) даёт сертификат Let's Encrypt вместо самоподписанного. Его A-запись должна указывать на сервер, а порт 80 быть открыт
- домен VPN (`--vpn-domain`) попадает в настройки клиентов вместо IP. Если сервер переедет, достаточно переключить запись, и настройки у людей останутся рабочими. Запись должна указывать на сервер до установки: установщик это проверит

**Компьютер** — Mac, Linux или Windows. Нужно уметь открыть терминал и вставить команду.

- Вход на сервер по ключу ничего дополнительного не требует. Для входа по паролю нужен `sshpass` или `expect`. На macOS `expect` уже есть, на Linux и в WSL поставьте `sshpass`:

  ```sh
  sudo apt install sshpass
  ```

- На Windows установщик не работает ни в PowerShell, ни в командной строке: он написан для оболочки Unix. Поставьте WSL — это Ubuntu внутри Windows. В PowerShell от имени администратора:

  ```powershell
  wsl --install
  ```

  Команда поставит Ubuntu и попросит перезагрузиться. После перезагрузки Ubuntu откроется сама и спросит имя пользователя и пароль — они нужны только внутри неё. Дальше откройте Ubuntu из меню «Пуск», поставьте в ней `sshpass` и вводите там все команды из этой инструкции. WSL есть в Windows 11 и в Windows 10 версии 2004 и новее.

## Установка

```sh
curl -fsSL https://raw.githubusercontent.com/AndreyLear/amnezia-vpn-server/main/bootstrap.sh -o bootstrap.sh
bash bootstrap.sh
```

Мастер спросит адрес сервера, пользователя SSH (по умолчанию `root`), пароль или ключ, домен панели, порт панели и домен VPN. Enter принимает значение в скобках. Те же ответы можно передать флагами:

```sh
./bootstrap.sh --ip 203.0.113.10 --panel-domain panel.example.com --vpn-domain example.com
```

| Флаг | Что задаёт |
| --- | --- |
| `--ip` | адрес сервера. С ним мастер ничего не спрашивает |
| `--user` | пользователь SSH, по умолчанию `root` |
| `--key` | файл ключа SSH, по умолчанию `~/.ssh/id_ed25519`, затем `~/.ssh/id_rsa` |
| `--password-env VAR` | взять пароль SSH из переменной окружения `VAR` |
| `--panel-domain` | домен панели с сертификатом Let's Encrypt (синоним `--domain`) |
| `--panel-port` | порт панели: 443 с доменом, 8443 без него |
| `--vpn-domain` | домен VPN для настроек клиентов (синоним `--client-domain`) |
| `--awg-port` | UDP-порт туннеля, по умолчанию 4500. Не берите 443 и 51820 |
| `--root` | каталог установки на сервере, по умолчанию `/opt/amnezia-vpn` |
| `--source URL` | скачать архив выпуска вместо упаковки локального репозитория |

Мастер печатает шаги `[1/9]` … `[9/9]`. Обычно образы скачиваются готовыми. Если на шаге 7 написано «Собираю образы», ждите 10–30 минут: процессор при этом загружен на 100%, так и должно быть.

В конце мастер печатает адрес панели, логин, временный пароль, адрес для клиентов и отпечаток сертификата. Сохраните это: пароль больше нигде не хранится.

```
Panel:     https://203.0.113.10:8443
Login:     admin
Password:  rZksiVMoEcPXsCQtFowec1+e
Endpoint:  example.com:4500
```

### Первый вход

1. Откройте панель по адресу из сводки. Без домена панели браузер предупредит о самоподписанном сертификате: сверьте отпечаток из сводки и продолжайте
2. [Смените пароль](#как-сменить-пароль-панели)
3. Нажмите «Добавить клиента» и подключите устройство, как описано в разделе [Клиенты](#клиенты)

### Что установщик включает сам

| Что | Что делает | Как выключить |
| --- | --- | --- |
| Защита SSH | `fail2ban`: пять неудачных попыток за десять минут — бан на час. Порт туннеля он не трогает: паролей там нет, а бан отрезал бы живого клиента | `--no-fail2ban` |
| IPv6 в туннеле | включается, если у сервера работающий IPv6. Проверяется реальный выход наружу, а не наличие адреса: у части хостеров адрес выдан, а трафик не ходит | `--no-ipv6` |
| Сторож | раз в минуту проверяет, что DNS в туннеле отвечает и туннель пишет статус. После двух сбоев подряд перезапускает сервис, не чаще раза в десять минут. Контейнер может быть запущен и не работать, а Docker этого не видит. Клиентов сторож не трогает: люди бывают офлайн | `--no-watchdog` |
| Проверка обновлений | раз в сутки сервер спрашивает GitHub, вышел ли новый выпуск, и панель показывает ответ. Сам ничего не скачивает и не ставит | `--no-update-check` |
| DNS в туннеле | сервер отвечает на имя панели адресом внутри туннеля, поэтому панель открывается и с включённым VPN, и без него | `--no-tunnel-dns` |

Любая проверка обновлений сообщает GitHub адрес вашего сервера. С `--no-update-check` этого не происходит, но о новых выпусках придётся следить самому. С `--no-tunnel-dns` порт 53 остаётся за DNS самого сервера, а с устройств, подключённых к VPN, панель по имени не открывается.

```sh
./bootstrap.sh --ip 203.0.113.10 --no-ipv6
```

Те же флаги понимает `install.sh`, если запускать его на сервере самому. Выбор запоминается на сервере: повторный запуск без флагов и обновление из панели ничего не включат обратно. Включить снова можно флагом без `no-`: `--fail2ban`, `--watchdog`, `--update-check`, `--tunnel-dns`, `--ipv6`.

Выключенный IPv6 убирается полностью: правила, маршрутизация и адреса в настройках клиентов. Обновление версии ваш выбор не меняет: сервер без IPv6 останется без него. Переключение IPv6 перезапускает туннель, связь у всех клиентов пропадает примерно на 15 секунд и возвращается сама, настройки перевыпускать не нужно.

## Клиенты

Клиент — одно устройство: телефон, ноутбук, роутер. У каждого свои ключи, отключение одного не задевает остальных.

Нажмите «Добавить клиента» и введите любое понятное имя. Панель выдаст адрес и создаст ключи. Дальше:

- **Телефон.** Меню клиента → «QR-код», отсканируйте в приложении
- **Компьютер или роутер.** Меню клиента → «Скачать конфиг» и импортируйте файл в приложение. Файл создаётся при скачивании и нигде не хранится

В том же меню: «Сведения» (имя, описание, MTU, ограничение скорости), «Отключить» (ключи остаются, клиент не подключается; включается обратно тем же пунктом) и «Удалить» (ключи стираются, старые настройки перестают работать насовсем).

Адреса выдаются из подсети `10.8.0.0/24`, то есть до 253 клиентов.

## Приложения

Подойдёт любой клиент AmneziaWG.

**AmneziaWG** — приложение только под этот протокол:

- iOS — [App Store](https://apps.apple.com/app/amneziawg/id6478942365)
- Android — [Google Play](https://play.google.com/store/apps/details?id=org.amnezia.awg)
- Windows — [релизы на GitHub](https://github.com/amnezia-vpn/amneziawg-windows-client/releases). Берите `amneziawg-amd64-<версия>.msi`. Для ARM есть `arm64`, для 32-битной Windows — `x86`. Для Windows 7 и 8 нужен выпуск не новее 2.0.2: у него есть файлы с `windows7` в названии

**AmneziaVPN** — общий клиент Amnezia с несколькими протоколами, для Windows, macOS, Linux, Android и iOS: [amnezia.org/downloads](https://amnezia.org/downloads). Если сервер у вас один, хватит AmneziaWG.

**Роутеры.** OpenWrt с пакетом `amneziawg` и Keenetic с поддержкой AmneziaWG настраиваются как обычный клиент, и тогда через VPN идёт вся домашняя сеть.

### Если туннель на роутере

Домашние устройства спрашивают имена у роутера, а не у вашего сервера, и настройки клиента до них не доходят. Поэтому нужны три шага:

1. **Единственный DNS на роутере — `10.8.0.1`.** Удалите остальные, включая выданные провайдером по DHCP
2. **Выключите на роутере DNS-over-HTTPS и DNS-over-TLS.** Иначе роутер продолжит спрашивать Cloudflare или Google по порту 443 мимо туннеля
3. **Выключите IPv6 от провайдера на подключении к интернету.** Если у устройства есть адрес от провайдера, оно выберет его, и трафик уйдёт мимо VPN с вашим настоящим адресом. В Keenetic: «Параметры IPv6» → «Настройка IPv6» → отключена

Проверка — с любого домашнего устройства, не с самого роутера:

```sh
curl -6 https://ifconfig.co
```

Адрес вашего сервера или ошибка — всё в порядке. Адрес провайдера — часть трафика идёт мимо туннеля.

**MTU.** Роутер на проводе несёт пакеты крупнее, чем телефон в мобильной сети, а сервер по умолчанию рассчитан на телефон. Для одного клиента MTU можно поднять: «Сведения» → MTU → «Изменить», допустимо 1280–1440. Это ускорит отдачу из дома наружу. Скорость в обратную сторону задаёт сервер, она общая для всех.

## Как сменить пароль панели

В панели формы смены пароля нет намеренно: так пароль нельзя подобрать через браузер. Он меняется командой на сервере:

```sh
ssh root@203.0.113.10 "cd /opt/amnezia-vpn && docker compose --env-file versions.lock \
  run --rm -T panel-init /app/panel auth set-password admin --password-stdin"
```

Команда ничего не спросит и ждёт ввода: наберите новый пароль и нажмите Enter. На экране он будет виден. Старый пароль не нужен.

## Бэкап

Бэкап — один файл со всем, что вы настроили: клиенты, их ключи и ключи сервера. Из него можно восстановиться на этом же сервере или на новом, а выданные людям настройки продолжат работать.

- **Скачать.** «Бэкап» → «Скачать». Файл называется `backup-2026-08-23.tar.zst` и занимает несколько килобайт
- **Когда.** После каждого изменения списка клиентов, а также перед переустановкой и сменой хостинга
- **Где хранить.** У себя, как пароль: внутри ключи сервера, файл не зашифрован. Не пересылайте его почтой и в мессенджерах. На самом сервере держать единственную копию нельзя: пропадёт сервер — пропадёт и она
- **Восстановить.** «Бэкап» → «Загрузить». Клиенты вернутся сразу, перезапуск не нужен. Пароль панели останется текущий. Пароль почты для уведомлений нужно будет ввести заново

## Переезд на другой сервер

1. Пока старая панель доступна, скачайте бэкап
2. Поставьте систему на новый сервер тем же мастером
3. В новой панели: «Бэкап» → «Загрузить»
4. Панель увидит, что бэкап снят на другом сервере, и спросит, какой адрес оставить клиентам:
   - **Адрес из бэкапа** — если люди подключаются по домену. Переключите A-запись домена на новый сервер, и все подключатся сами
   - **Адрес этого сервера** — если подключались по IP. Раздайте людям новые настройки из панели

## Обновление

С версии 2.9.0 панель сама показывает, что вышел новый выпуск, и обновляет сервер по кнопке. Заходить по SSH не нужно.

Первый раз приходится по-старому: служба обновления приезжает вместе с выпуском, и на сервер, установленный раньше, её надо сначала доставить. Так же обновляются те, кто отключил проверку обновлений (`--no-update-check`): без неё сервер не знает о новых выпусках.

Обновление — это тот же мастер, запущенный ещё раз. Он помнит настройки сервера, флаги повторять не нужно:

```sh
curl -fsSL https://raw.githubusercontent.com/AndreyLear/amnezia-vpn-server/main/bootstrap.sh -o bootstrap.sh
bash bootstrap.sh --ip 203.0.113.10
```

Домен VPN остаётся прежним, даже если не указать `--vpn-domain`. Вернуть адрес сервера можно явно: `--vpn-domain ""`. Настройки клиентов перевыпускать не нужно. Связь пропадает на несколько секунд и возвращается сама.

Мастер обновляет и то, что живёт на самом сервере: правила файрвола, параметры ядра, службы. Новое, вроде IPv6 в туннеле, приходит только так.

`docker compose pull` не помогает: версия образов берётся из файла прошлой установки, и скачается та же версия, которая уже стоит.

## Удаление

```sh
ssh root@203.0.113.10 "bash /opt/amnezia-vpn/cleanup.sh"
```

Скрипт покажет, что собирается удалить, и ничего не тронет. Чтобы выполнить, добавьте `--yes`. Он удаляет только созданное установщиком. Пакет `fail2ban` остаётся.

## Если что-то не работает

**Сайты открываются, а видео не грузится.** Почти всегда MTU: мелкие пакеты проходят, крупные теряются. Установщик ставит 1360, а если канал сервера уже, то меньше (не ниже 1280). Обычно помогает переустановка. Если нет — уменьшите MTU в приложении на клиенте, например с 1360 до 1280.

**Клиент не подключается после переезда.** Проверьте, куда указывает домен: `dig +short example.com`. Должен быть адрес нового сервера.

**Панель не открывается.** Проверьте, что сервисы запущены:

```sh
ssh root@203.0.113.10 "docker ps"
```

В списке должны быть `amnezia-vpn-panel-1` и `amnezia-vpn-awg-1`.

## Безопасность

Проект рассчитан на один сервер и одного администратора. Вход в панель — только по логину и паролю, без второго фактора. После пяти неудачных попыток за 15 минут с одного адреса вход блокируется. Бэкап и доступ по SSH равны доступу к VPN, берегите их. Подробнее — в [SECURITY.md](SECURITY.md).

## Как это устроено

На сервере четыре контейнера: панель (хранит данные в SQLite), AmneziaWG, DNS для подключённых клиентов и разовая задача инициализации. Панель слушает только сам сервер, наружу её выставляет nginx с сертификатом. Всё остальное восстанавливается из базы, поэтому бэкап базы возвращает и клиентов, и ключи сервера.

Настройки клиента отправляют в туннель и IPv6, чтобы он не шёл мимо VPN с вашим настоящим адресом. Если туннель IPv6 не несёт, такие соединения обрываются, и приложения переходят на IPv4.

Туннель работает на UDP 4500. Порт 443 открыт почти везде, но это порт QUIC, и мобильные операторы придерживают его, чтобы притормозить видео. Туннель на нём попадал под то же ограничение: 20 Мбит/с против 45 на порту 4500 и 40 вообще без туннеля. Порт 4500 занят IPsec, на котором работают корпоративные VPN, поэтому его пропускают.

DNS внутри туннеля нужен из-за панели. Она стоит на адресе, где туннель заканчивается. Пакет на этот адрес в туннель не попадает, а маршрут в обход iOS не создаёт, так что без подмены имени панель не открывалась бы именно с подключённых устройств. Клиенту выдаётся наш DNS. Если в туннеле есть IPv6, к нему добавляется публичный запасной: наш остановится, а имена продолжат разрешаться.

Без IPv6 запасного нет: публичный DNS отдавал бы IPv6-адреса, которых туннель не несёт, и получилось бы «страницы открываются, а видео не грузится» без видимой причины. Здесь отказ виден сразу, а сторож поднимает DNS в течение минуты.
