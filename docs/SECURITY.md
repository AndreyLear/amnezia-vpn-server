# Security

Актуальные инварианты и контрмеры на момент M6. Полный red-team hardenинг
запланирован на M9; аутентификация веб-панели — M7.

## Инварианты

1. **Секретный материал никогда не покидает панель.** Приватные и
   preshared-ключи не попадают в HTML-ответы, статус, ошибки и логи:
   - производитель статуса (`awgstatus`, M5) отбрасывает
     `private_key`/`preshared_key` ещё на этапе парсинга; панель
     принципиально не читает ключи из БД для отрисовки;
   - типы данных рендеринга не содержат полей ключей
     (см. `M6_AUDIT.md` §2.1.8), рендеринг — только `html/template`
     (autoscape), никакого raw-вывода;
   - логирование эндпоинтов с id допустимо; конфигов и ключей — запрещено;
   - `test_m6_live.sh` шаг [7] и unit-тесты сканируют ответы/логи на
     ключи.
2. **Порт панели слушает только loopback** (`127.0.0.1:8787` в compose,
   без `0.0.0.0`) до введения аутентификации (M7). Подключение
   межконтейнерного HTTP отсутствует; полный красный порт — только с M7.
3. **Искажённый входной файл не отражается в ответе.** Ошибка парсинга
   `status.json` → generic «status error»; содержимое файла (в т.ч.
   секретные строки) никогда не включается в ответ.
4. **Инъекции HTML/reflection**: любой ввод (имена клиентов, flash-сообщения)
   экранируется `html/template`; фразы ошибок — фиксированные строки,
   детали запроса не эхографируются.

## Контрмеры HTTP-слоя

- **Таймауты сервера**: `ReadHeaderTimeout 5s`, `ReadTimeout 10s`,
  `WriteTimeout 15s`, `IdleTimeout 60s`; `MaxHeaderBytes 1 MiB`.
- **Лимит тела запроса**: POST ≥ 64 KiB → `413 Request Entity Too Large`
  (`http.MaxBytesReader`), запись в БД не выполняется.
- **Security-заголовки** на всех ответах:
  `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: no-referrer`,
  `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'`,
  `Cache-Control: no-store`.
- **Восстановление после panic**: generic-страница 500, значение panic
  видно только в серверных логах, никогда клиенту.
- **Path traversal**: контент — только из embedded FS; скачивание конфига
  по id из БД (строгий `int64`), а не по пути файла.

## Файловые права

- SQLite-база и `status.json` — 0600, запись атомарная
  (tmp → fsync → rename → fsync каталога).

## Риски и план

- **CSRF** не релевантен до cookie-сессий: в M7 вводится связка
  PRG + CSRF-токен (зафиксировано в архитектуре).
- **Slowloris/полный hardening** — M9.
- **DoS через QR**: полезная нагрузка — конфиг фиксированного малого
  размера, QR генерируется в памяти без записи на диск, риск ~0.
- Атрибуция и scope: `internal/auth` — заготовка строго M7.

## Рекомендации по эксплуатции

- Не открывать порт панели наружу до M7 (аутентификация).
- Бэкапы `data/*` содержат приватные ключи — хранить с правами
  ограниченного пользователя.
